### Root cause (verified, not inferred)

`scripts/p3_forge_acceptance.py` compared Docker's container-inspect `Image`
field — which is always an image ID — against `image.split("@",1)[-1]`. The P4
gate passed the signer image by tag (`echo-certforge-signer:p4-b9f93c9-a`), so
the comparison was tag-string vs ID-string and could never match. Verified on
FORGE: `docker image inspect echo-certforge-signer:p4-b9f93c9-a` →
`sha256:5ebade8331a05c3768f05e8c316313598f1f11d2057173cac64464ce43a10bb4`,
exactly the ID the container ran. The container ran the correct image; the
check produced a false mismatch.

### Fix applied (commit `307667a`, gate-validation still pending)

`run_signer_container` now resolves the reference (tag/digest/ID) to the exact
local image ID via the Docker API before creation, creates the container bound
to that ID, and compares ID-to-ID. Unresolvable references raise (fail-closed).
This is strictly stronger than the previous check (it also removes the
tag-retag race between creation and validation). Four unit tests cover
resolution, fail-closed, no-false-mismatch, and true-mismatch
(`tests/test_p3_signer_image_identity.py`). **The fix has NOT been validated by
the real FORGE gate — only the next full run can do that.**
